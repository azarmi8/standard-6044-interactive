# LEARNING MAP — Standard 6044:1397 Interactive

این نقشه، معماری آموزشی v1.0 را برای 22 واحد یادگیری تعیین می‌کند. هر واحد چهار لایه دارد:
1. Source — آنچه استاندارد می‌گوید، با ارجاع.
2. Explain — توضیح ساده و آموزشی، جدا از متن منبع.
3. Apply — اتصال به کار واقعی کارخانه/QC.
4. Practice — تمرین/تصمیم/سناریو با پاسخ و مبنای منبع.

## Standard unit screen

هر واحد در موتور نهایی این ترتیب را دارد:

### 1. Source
- عنوان بند/پیوست
- خلاصه وفادار به منبع
- صفحه/بند/جدول
- نشان واضح SOURCE

### 2. Explain
- توضیح فارسی ساده
- اصطلاحات تخصصی با تعریف
- نشان EXPLANATION

### 3. Apply
- یک موقعیت واقعی کارخانه/QC
- ورودی‌های قابل مشاهده
- تصمیم مورد انتظار
- نشان FACTORY APPLICATION

### 4. Practice
حداقل یکی از:
- MCQ
- درست/غلط
- ترتیب مراحل
- تصمیم عددی/بازه‌ای
- سناریوی پذیرش/بازبینی
- محاسبه شفاف

هر پاسخ شامل نتیجه، دلیل، منبع و توضیح خطای رایج است.

## Source/education separation

موتور نباید این سه نوع محتوا را مخلوط کند:

- SOURCE: الزام/عدد/جدول/فرمول مستند.
- EXPLANATION: ساده‌سازی آموزشی؛ الزام جدید ایجاد نمی‌کند.
- EXERCISE: داده سناریو برای تمرین؛ اگر فرضی است باید صریحاً «سناریوی آموزشی» برچسب بخورد.

## Difficulty levels

- L1 — شناخت
- L2 — درک
- L3 — کاربرد
- L4 — تحلیل/تصمیم

فصل‌های 1–4 عمدتاً L1–L2 شروع می‌شوند؛ فصل‌های 7–15 و پیوست‌های A–F باید تا L3–L4 برسند.

## Architecture rule

محتوای واحدها نباید منطق انیمیشن یا UI را داخل Markdown قفل کند. Markdown منبع آموزشی است؛ موتور باید timing، beats، interaction و assessment را از داده/پیکربندی قابل توسعه دریافت کند.

## Phase 2 exit gate

Phase 2 زمانی تمام است که:
- هر 22 واحد هدف یادگیری داشته باشد؛
- مسیر Source → Explain → Apply → Practice مشخص باشد؛
- نوع تعامل اصلی هر واحد مشخص باشد؛
- سطح دشواری مشخص باشد؛
- هیچ تعامل عددی بدون منبع یا برچسب سناریوی آموزشی وارد طراحی نشود.


## Importance / priority

### P0 — Core operational knowledge
Units: 06, 07, 08, 09, 10, 11, 12, 14, 15

این واحدها مستقیماً به سفارش، تولید، تحویل، نمونه‌برداری، آزمون، پذیرش و کنترل تولید وصل‌اند و در نسخه نهایی باید تجربه تعاملی قوی داشته باشند.

### P1 — Foundation and engineering support
Units: 01, 03, 04, 05, 13, A, B, C, D, E, F

این واحدها پایه تصمیم‌های P0 یا سیستم کنترل تولید و ارزیابی را تقویت می‌کنند.

### P2 — Reference / traceability support
Units: 02, G

این واحدها برای جست‌وجو، ردیابی مراجع و فهم تغییرات استاندارد مهم‌اند، اما نسبت به مسیر عملی QC تعامل کمتری دارند.
