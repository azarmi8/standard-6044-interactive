# راهنمای نگارش فارسی محصول — استاندارد ۶۰۴۴

## هدف

زبان این کتاب تعاملی باید برای مهندس، مسئول کنترل کیفیت، کارشناس آزمایشگاه و کاربر عمومیِ علاقه‌مند به بتن طبیعی، دقیق و قابل‌فهم باشد. متن رابط کاربری نباید شبیه ترجمه ماشینی، متن تبلیغاتی یا اصطلاحات نمایشیِ فاقد کاربرد باشد.

## اصول

1. متن استاندارد منبع‌محور است و بدون ممیزی بندبه‌بند بازنویسی نمی‌شود.
2. متن آموزشی باید کوتاه، مستقیم و کاربردمحور باشد.
3. لحن پیش‌فرض رابط کاربری محترمانه و عملی است: «انتخاب کنید»، «بررسی کنید»، «ثبت کنید».
4. از اصطلاحات رایج صنعت ساختمان و آزمایشگاه ایران استفاده شود؛ در صورت وجود اصطلاح دقیق‌تر در استاندارد، اصطلاح استاندارد مقدم است.
5. برای هر مفهوم، یک واژه ثابت انتخاب شود و در کل محصول همان واژه به‌کار رود.
6. انگلیسی فقط برای شناسه فنی، کد آزمون، نام API یا برچسبی که واقعاً ارزش فنی دارد باقی بماند.

## اصطلاحات تخصصی که باید حفظ شوند

اسلامپ، جریان اسلامپ، اسلامپ‌فلو در صورت نیاز به نام تجاری/بین‌المللی، بتن خودتراکم، تراک‌میکسر، طرح مخلوط، آب مؤثر، آب کل، رده مقاومت، مقاومت مشخصه، آزمونه، عمل‌آوری، نمونه‌برداری، ردیابی، انطباق، اقدام اصلاحی، نظارت ادواری، بازرسی فوق‌العاده.

## نام‌گذاری رابط کاربری

- «پخش»، «مکث»، «بازپخش»، «تمام‌صفحه»، «شروع مطالعه»، «ادامه مطالعه»، «جست‌وجو»، «نمایش نتیجه» و «شروع دوباره» مناسب‌اند.
- عنوان هر شبیه‌ساز باید دقیقاً بگوید کاربر چه کاری انجام می‌دهد؛ نمونه: «مقایسه دو نمونه»، «محاسبه مقاومت فشاری هدف»، «بررسی خواص بتن تازه».
- از عبارت‌های مبهم مثل «اجرای عملیات»، «سامانه هوشمند»، «هسته کنترل‌گر»، «تحلیل پیشرفته» بدون توضیح کاربردی استفاده نشود.

## زبان سناریو و آزمون

ترجیح: «این سناریو آموزشی است. اعداد واردشده مربوط به تمرین‌اند.»

به‌جای: «این ابزار یک شبیه‌ساز هوشمند برای بازسازی زنجیره ... است.»

## زبان نتایج

نتیجه باید اول وضعیت را بگوید و سپس دلیل کوتاه را ارائه کند.

نمونه:
«مدارک سفارش کامل نیست.»
«زمان نمونه‌برداری در بازه مجاز قرار دارد.»
«نتیجه با معیار این تمرین منطبق نیست.»

## قانون نهایی

هیچ واژه‌ای صرفاً برای القای حس هوش مصنوعی، پیشرفته‌بودن یا لوکس‌بودن وارد رابط کاربری نشود. متن باید کاری را که کاربر می‌تواند انجام دهد، روشن و دقیق بیان کند.
