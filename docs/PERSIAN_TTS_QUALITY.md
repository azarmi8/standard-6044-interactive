# PERSIAN TTS QUALITY CONTRACT — Standard 6044:1397

هدف: روایت این کتاب آموزشی مهندسی باید از نظر تلفظ فارسی، مکث، عددخوانی، واحدها و واژه‌های تخصصی قابل اعتماد باشد. تولید فایل صوتی به‌تنهایی معیار پذیرش نیست.

## خط قرمز
هیچ فایل صوتی وارد release نمی‌شود مگر اینکه متن مرجع مشخص باشد، تلفظ فارسی بازبینی انسانی شده باشد، اعداد و واحدها کنترل شده باشند، واژه‌های فنی در صورت نیاز reading override داشته باشند و صوت با transcript همان Beat تطبیق داشته باشد.

## راهبرد TTS
- گزینه local/offline: Piper با مدل‌های فارسی fa_IR.
- گزینه benchmark رایگان: Edge TTS با voice فارسی ایران.
- مدل‌های دیگر فقط پس از تست کیفیت وارد pipeline می‌شوند.
- هیچ provider یا API پولی dependency اجباری v1.0 نیست.

بررسی اولیه GitHub نشان داده Piper مدل‌های فارسی fa_IR دارد و پروژه‌هایی برای بهبود phonemization فارسی و voiceهای فارسی موجودند. اینها کاندید هستند، نه تضمین کیفیت.

## Pronunciation dictionary
برای واژه‌های حساس، متن صوتی از متن نمایشی جدا می‌شود:
- displayText: متن رسمی و قابل نمایش
- spokenText: متن آماده TTS با نشانه‌گذاری لازم برای تلفظ
- readingNote: توضیح تلفظ برای QA

نمونه‌های حساس: ۶۰۴۴، ۱۳۹۷، ۳۲ درجه سلسیوس، fc، SCC، ASTM و ISIRI.

## Number policy
عددهای فنی نباید کورکورانه به TTS سپرده شوند. برای هر عدد، واحد و معنای آن مشخص باشد؛ اعشار، درصد، دما، حجم و مقاومت با خوانش فارسی کنترل شوند؛ نمادهای ریاضی به زبان طبیعی تبدیل شوند.

## QA sample
هر voice candidate ابتدا با یک benchmark کوچک آزمایش می‌شود: جمله عمومی فارسی، عدد فارسی، عدد + واحد، نام استاندارد، مخفف فنی، جمله دارای نماد، جمله مهندسی طولانی و متن شامل میانگین، مقاومت مشخصه، نمونه‌برداری و انطباق.

قبولی اولیه فقط وقتی است که هیچ خطای تلفظی بحرانی در این بسته وجود نداشته باشد.

## ممنوع
- تولید انبوه صوت قبل از تأیید voice و pronunciation dictionary.
- اصلاح خودکار متن رسمی بدون حفظ نسخه نمایشی.
- ادعای تلفظ صحیح صرفاً بر اساس خروجی یک مدل.
